# AI Usage

AI (Cursor) использовался как ускоритель реализации: черновики кода, рефакторинг по готовым решениям, рутина.  
Архитектуру, продуктовые решения, проверку контрактов и финальный код принимал и контролировал я.

## Какие части делались с AI

- Черновая генерация UI-компонентов и разметки страниц по уже выбранному дизайну / структуре.
- Бойлерплейт: хуки Query/Mutation, формы RHF, MSW handlers, seed-данные.
- Shared form-kit (`TextField`, `ComboboxField`, `DatePickerField`, `RangeInputField`, `TriStateField`) на RHF `Controller` + Radix.
- Модель фильтров списка: Zod search schema, `validateSearch`, маппинг в `AuctionListRequest`, MSW-фильтрация.
- Drawer фильтров + Zustand-стор открытых drawer’ов (`Set` имён + `drawerApi`).
- Юнит-тесты на уже написанную чистую логику (search / request / chips / schema ставки).
- Правки по замечаниям в процессе (типы, мелкие баги, тексты README).
- Помощь с рутиной: переименования, вынос констант и отдельных модулей, оформление документов.

## Какие решения я принял сам

- Архитектура FSD: границы `pages` / `features` / `entities` / `shared`, отдельные фичи фильтров и ставки.
- Стек и инфраструктура проекта: Vite, TanStack Router/Query, Zustand только для UI-state, axios + `ApiError`.
- Источник правды — официальная `openapi.auctions.v0.json` + `openapi-typescript`.
- Фильтры списка только через URL search params + Zod с безопасными fallback без сохранений в localStorage.
- Синк фильтров в URL — явный `onChange → navigate(search)`, debounce только у текстового поля на уровне фичи
- Drawer’ы контролируются через Zustand (`open: Set<string>`), открытие/закрытие снаружи через `drawerApi`, без `trigger` внутри `Drawer`.
- Не предлагать ставку, если пользователь уже `Leading` (не перебивать себя), поверх `can_set_bet`.
- Визуальная составляющая: светлая тема «референс HH.ru», использовал часть компонентов из radix/ui и кастомные (`Button`, `Card`, `Chip`, form-kit).
- Prefetch detail по hover intent с onleave через общий debounced helper + хук.
- Ограничение по `step` на карточке списка: не подделывать поле в list DTO, зафиксировать в README.

## Какие AI-предложения были отклонены / переделаны

- Тянуть detail на каждую карточку списка ради `step` — слишком дорого и ломает смысл list API.
- Дописывать `step` в MSW list «для красоты» вразрез с OpenAPI — отказался.
- Оставлять форму ставки при статусе `Leading` только потому что `can_set_bet === true`.
- Синк фильтров через `form.watch` + `useEffect` / отдельный sync-hook — переделано на явный `onChange` в URL (проще и контролируемее).
- Debounce внутри `TextField` — вынесен наверх, в фичу фильтров.
- Хранить города как `{ id, name }` — оставили `string[]` под контракт фильтров.
- Раздувать scope тестами UI/MSW/e2e сверх рекомендаций ТЗ.
- Часть ранних UI-черновиков (лишние карточки, шум в первом экране) — пересобирал под более спокойный UX.

## Что проверял особенно внимательно

- Соответствие запросов/ответов OpenAPI (enum, nullable, 422 `validation_failed`).
- Что MSW после POST bets реально обновляет цену, `status_mobile`, историю ставок и list-карточку.
- Zod search params: мусор в URL не валит страницу.
- Инвалидация Query после ставки (list / detail / bets).
- Сценарии `hide_bets_history`, `can_set_bet = false`, empty/error на списке и ставках.
- Границы FSD: features не протекают в entities, страницы только собирают слоты.
- Поля при URL-controlled форме (`values` из search): локальный state у `TextField` / `RangeInput`, чтобы ввод и очистка не затирались старым URL до debounce.

## Какие риски остались

- MSW — учебный in-memory store, не полный бэкенд (нет auth, гонок, пагинации на огромных данных).
- В list DTO нет `step` — требование ТЗ к карточке списка формально не закрыто данными схемы.
- Seed покрывает основные кейсы, но не все комбинации enum/флагов из OpenAPI.

## Что улучшил бы при ещё одном дне

- Визуальный интерфейс подбор css токенов и юнитов
- Более богатый seed под редкие edge cases (несколько hide-флагов сразу, FixPrice, отмены ставок).
- Точечные тесты на `toApiError` (склейка нескольких 422 `errors[]`).
- Лёгкий visual QA чеклист в CI (lint + test + build уже есть локально).
- Подчистить оставшийся шум в UI и выровнять копирайт на всех empty/error состояниях.
